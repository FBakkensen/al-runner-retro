Running agents through one repository:
what held, what slipped

A retrospective on the multi-agent workflow around StefanMaron/BusinessCentral.AL.Runner and its AL-language corpus, where two operators run independent agent loops that talk to each other only through GitHub issues and pull requests.

window 2026-08-10 → 2026-09-09 · snapshot 2026-09-09 · 82 findings: 29 works / 40 mixed / 13 broken · every claim links to its issue, PR or commit

The pipeline is fast and the code that lands is sound. 796 pull requests merged in 30 days at a median of 0.8 hours, 625 of 638 code PRs shipping a test and 25 of 30 sampled tests proving a concrete value, zero code reverts, and a corpus-linkage gate that closed a 62% declaration gap the day it became required. What is slipping is everything around the code: the governance agents load on every turn grew 7.8× and reversed itself eight times, the claim protocol is blind during the minutes when collisions actually start, labels stop being true once work finishes, and a runner PR can merge before its corpus verdict exists. The dominant pattern across the five dimensions: a required check ends an incident class; a paragraph narrates it.

Ranked changes

each backed by the findings it cites; workflow changes are proposals for the maintainer
  1. 1

    Turn the recurring prose rules into hooks and gates

    Every incident class that got a required check stopped (unhatched merges 37 → 7 → 0; ci-skip once, never again). The classes that stayed prose kept recurring until a tool arrived. Add a PreToolUse hook that rejects git stash and backgrounded CI waits, make the code-navigation hook block instead of advise for impl and reviewer agents, and add path-based required checks for CHANGELOG.md and the corpus submodule. Then each of those rules shrinks to one line.

    Backed by c-1 c-3 c-11 d-5 c-6Lands in .claude/hooks, tools/ (maintainer-owned workflows for the path gates)
  2. 2

    Cut the auto-loaded governance surface back under 50 KB

    Rules plus CLAUDE.md grew 17 KB → 133 KB in 30 days, 35% of it dated incident narrative, and each instruction is stated in 4.35 files on average. Apply the repo's own claim-plus-citation standard (#3402) to .claude/: a rule is a claim, a citation and the trap. Move every 'incidents this rule is made of' section to docs/incidents/, give each instruction one canonical home, and pin it with a drift test so a restatement fails CI.

    Backed by c-9 c-10 c-16 b-19 c-4Lands in .claude/rules, docs/, tools/test_*.py
  3. 3

    Make a claim visible the moment it is made, and namespace shared paths per session

    The open-PR check cannot see work in its first 6-70 minutes, which is exactly when every collision started; both post-rule collisions happened in that window. Open a draft PR with Closes #N as the first act after claiming. Key worktrees, scratch dirs and container names on identity plus session, not identity alone, because a shared worktree path let one loop push into another's branch. Either stop minting numbered identities (110 labels exist) or drop the agent label from ownership entirely.

    Backed by b-2 b-3 b-5 d-13 d-18 c-7Lands in .claude/agents/impl-agent.md, .claude/rules/check-open-prs-before-claiming.md, tools/preflight.py
  4. 4

    Do not arm auto-merge until the cited corpus PR has a verdict

    The linkage gate checks that something was declared, not what happened to it. Four post-gate runner PRs merged while their corpus PR was still open (two by 19 hours), and four merged runner PRs cite corpus PRs that closed unmerged, so those surfaces never got a service-tier verdict. Resolve each Corpus-PR line to its state; OPEN or CLOSED-unmerged blocks arming. Run one sweep for the four orphans and file a catch-up issue per surface.

    Backed by e-5 e-2 e-4Lands in tools/ci-wait.py or the advisory linkage job; a one-off sweep
  5. 5

    Clean labels on close and merge, and catch the undeclared Closes

    561 of 872 closed issues still carry status: in-progress and 645 an agent label, so every label query has to filter on state first. 31 merged PRs are named for an issue they never declared, leaving 12 issues open and invisible to the ready queue. Strip status and agent labels when an issue closes, flip 'Part of #N' issues back to ready at merge, and have the gate require Part of #N when the branch's issue is absent from the closing references.

    Backed by b-7 b-8 b-20 b-9Lands in orchestrator merge pass, pr-gate (maintainer-owned), .claude/agents/impl-agent.md
  6. 6

    Give the reviewer a fixed verdict line and post it as a GitHub review

    1 of 796 merged PRs has a GitHub review object; review happens in comments with at least five header styles, so a verdict cannot be extracted and a FIX-FIRST can be armed by mistake. End every reviewer comment with 'Verdict: MERGE | FIX-FIRST | HOLD (reason)', post it through the review API, and split a cheap arm-check (merge-tree, ci-wait, linkage state) from the full review so the two thirds of reviewer spend that only confirms a mergeable PR gets cheaper.

    Backed by a-7 e-11 e-12Lands in .claude/agents/reviewer.md, tools/
  7. 7

    Manage the ready queue as a queue

    Open issues went 8 → 237 in two weeks; 115 are ready, 39 older than a week, 113 of them filed by one operator while the other pool fixes its own filings. Print the ready-queue age histogram in every cycle summary, pick oldest-first when nothing else orders the queue, let the fbk coordinator draw from the shared queue once its own filings are empty, make filing idempotent (five issues were filed three times by API retries), and route expectation-drift fixes through one owner.

    Backed by a-2 b-10 b-12 b-21 b-17Lands in .claude/skills/orchestrating-a-session, autonomous-cycle, agent briefs
  8. 8

    Bound impl-agent runs and batch the coordinator's CI reads

    Impl agents median 116 tool calls, 15 of 64 over 200, and are 87% of subagent spend; 70% of measured spend is the 1M-context tier and cache reads are 95% of billed tokens, so cost is round trips times accumulated context. Put a call budget and a checkpoint hand-back in impl-agent.md, default to the standard context tier, rotate the coordinator session after a fixed number of cycles, and replace per-PR ci-wait plus gh run list calls with one batched sweep read.

    Backed by d-2 d-8 d-10 d-21 d-4Lands in .claude/agents/impl-agent.md, tools/, autonomous-cycle skill
  9. 9

    Change how rules get written

    Eight guidance reversals in 30 days, three the same day; 18 of 87 governance commits correct earlier guidance; one stale contradiction is still on main (autonomous-cycle/SKILL.md line 538, 'the GitHub assignee is the lock'). Require a rule to cite two independent instances or a measurement before it states a direction, land a governance tool with its tests and a 48-hour watch before writing its prose, and pin directional statements with drift tests.

    Backed by c-8 c-15 c-17 c-2Lands in .claude/rules process; docs/incidents/
  10. 10

    Take the pressure off the hot files

    Program.cs was touched by 150 merged PRs, the count baseline by 152, RecordPatches.cs by 68 and MockTestPage.cs by 65; consecutive merges on those files land under 48 hours apart almost every time and 26% of merged PRs needed a force-push. Generate the count baseline in CI instead of committing it per PR, split RecordPatches.cs and MockTestPage.cs into partials as Program.cs has been, and show the newest main floor verdict next to the PR verdict so an inherited red is visible before arming.

    Backed by a-6 e-6 e-8Lands in tools/, AlRunner/ refactor, ci-wait.py
  11. 11

    Record the answers the operator keeps having to repeat

    On this operator's side, 41 of 260 typed messages were corrections, and three themes recurred 3+ times after being written down: keep working while issues remain (7), find the root cause of missing harness tools (7), give a clean status (6). Encode the first as a hard stop condition in the loop skill, write one verified memory note for the second, and carry defaults for the 58 recurring questions in the resume skill.

    Backed by d-14 d-15 d-16 d-17Lands in operator memory, .claude/skills/autonomous-cycle

Method and what could not be measured

Population analysis over all 796 merged runner PRs in the window (raw/runner_prs.jsonl, raw/corpus_prs.jsonl, raw/runner_comments.jsonl, raw/gitlog_main.tsv, raw/gitlog_files.txt), with pools re-derived from headRefName (agent/impl-N, agent/stma-auto-N, agent/fbk-N, coord/orchestrator, claude/*, other) and Corpus-PR / Corpus-NA / AL-observable re-derived with the gate's own path list and regex (GraphQL bodyText renders the URL as owner/repo#N, so both spellings were accepted). A 30-PR stratified sample (13 impl/stma-auto/coord, 9 fbk, 8 claude/other, spread over the five weeks, code-touching only) was read via git show on the squash merge commit, extracting added assertion lines from test paths and, for pin bumps, the corpus diff between the two pins. Expectation-manifest growth was counted two ways: +/- 'Mode' lines per commit under tests/expectations/ (211 commits) and entry counts at the window-start tree vs upstream/main. One non-snapshot read was used: gh run list for main-verdict-floor.yml (122 runs, 2026-09-06..09-09) and test-matrix.yml on main (400 newest runs, reaching back only to 2026-09-04). Not measured: whether any sampled test was executed on CI (only whether it exists and what it asserts), the content of reviewer findings reported agent-side but never posted, and main verdicts before 2026-09-04. Data caveats measured, not assumed: the snapshot's PR file list disagrees with the squash merge commit for 7 of 796 merged PRs (0.88 percent; #1909, #2333, #2365, #2736, #2896, #2977, #3551), flipping the AL-observable flag once (#2736, whose 161-file diff exceeds the 100-file GraphQL page) and the test-path flag once, so population counts below are unchanged within one PR; and the snapshot holds only one commit node per PR (420 merged PRs have more), so 'a push followed the review comment' is inferred from the head commit date or a force-push event and is a lower bound that a rebase can also satisfy. The impl stratum of the sample drew 10 impl, 2 stma-auto and 1 orchestrator PRs; stma-auto (177 merged, nearly all in weeks 3-4) is under-represented relative to its share.

Method and caveats

Data. One read-only snapshot taken 2026-09-09: 829 runner PRs and 2,423 issues updated in the window (REST and GraphQL), 1,458 issue comments, 14,800 repo-wide issue events back to 2026-08-09, 271 corpus PRs and 200 corpus comments, 967 commits on main, the full git history of .claude/ and CLAUDE.md, and one operator's 45 Claude Code session transcripts with 164 subagent transcripts. Nothing on GitHub was written, labelled or commented during the analysis.

Operators. The maintainer's agents push under the StefanMaron and claude logins with pools impl-N, stma-auto-N, orchestrator and coord; the second operator's agents push under FBakkensen with pool fbk-N. Because every loop of one operator acts under one login, collisions between loops of the same operator are invisible in the event log and were reconstructed from PR pairs, branch names and comment text.

Known limits. The GraphQL file list caps at 100 files, which flipped one PR's classification (#2736); the snapshot carries one commit node per PR, so "a push followed the review" is a lower bound a rebase also satisfies; the never-block-on-CI and verify-execution rules have two days of post-change data; no impl-agent transcripts exist on this operator's side before 2026-09-02, so the code-navigation guidance has no before/after here; corpus check-run status was not pulled, so corpus waiting time uses last push to merge as a proxy.

Cost figures in section 5 cover one operator's sessions only. The harness cost record exists for 17 of 45 sessions and is a point-in-time snapshot (one session with 44 subagent spawns records USD 16 against roughly USD 1,100 by token usage), so the measured sum is a floor and the estimate applies per-model rates derived from those 17 records to every session's token usage. Read the ratios (share by model tier, by agent type, cache-read share, cost per merged PR) rather than the totals.

Counting basis. PRs and issues are counted by creation inside the window unless a finding says otherwise; pools come from the branch prefix (agent/<pool>/…) cross-checked with the author login. Where two dimensions measured the same thing with different instruments, the finer measurement is cited and the other footnoted (b-2 versus c-7 on post-rule collisions). Small disagreements that remain are basis differences, not errors: closed-unmerged runner PRs are 25 counted by creation date (section 2) and 27 by update date (b-17); corpus PRs are 269 opened / 261 merged by creation date and 271 / 263 by update date; the impl pool is 411 by branch prefix (section 2) and 407 when the author login is also required (section 1).

Verdicts. works the mechanism does what its rule says, with evidence; mixed it works in part or the evidence is thin; broken a measured failure that recurs or that nothing currently detects. Confidence is the analyst's, stated per finding with its reason.
